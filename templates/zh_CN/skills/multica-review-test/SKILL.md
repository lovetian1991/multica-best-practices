# 测试产物专业评审（测试评审）

本 skill 提供对 **测试产物（功能/接口用例、T2 补充清单、T3 测试报告）**的结构化专业评审框架。调用方为 `测试评审`，评审对象为 `测试专家` 经 `multica-artifact-test-sync` 回传的链接，以及对应小队负责人派活时给的验收标准 + 相关实现变更链接。

## 什么时候用

- 测试评审收到对应小队负责人派发的「评审测试产物」任务时（T1 功能用例 / 接口用例 / T2 补充 / T3 报告均适用）。
- 测试产物修改后进入复审轮次时（对照上一轮修改清单逐条核对）。

## 评审维度（逐项给结论）

1. **覆盖深度**：正常 / 边界 / 异常 / 权限 / 兼容路径是否覆盖。
2. **验收对应**：每条 AC- 是否都有可执行用例或报告证据支撑。
3. **覆盖率合理**（T2/T3）：覆盖率指标是否真实反映风险点，有无掩盖关键未覆盖路径。
4. **结论真实**（T3）：通过/失败是否基于真实执行证据，缺陷是否可复现。
5. **契约一致**：接口用例参数、断言是否对齐 后台开发专家 契约。

## 输出格式

```text
【测试产物评审】<测试链接>
结论：PASS / FAIL
阻断项（FAIL 时必填，每项含 理由 / 涉及点 / 修改方向）：
- ...
建议项（非阻断）：
- ...
与上一轮修改清单核对（复审时）：已解决 X 项 / 未解决 Y 项
轮次：第 N / 3 轮
```

结论与修改清单**汇报给对应小队负责人**，不自行改用例、不自行通知测试专家。

## 边界

- 只评测试产物（**写**与**执行报告**），不评架构、需求、UI、前端/后端实现、代码单测。
- 不替代对应小队负责人的通用门禁（`multica-verification` skill）。
- 实现层质量交对应专属评审员，你只管测试产物本身的专业度。
- 第 3 轮仍 FAIL → 标注「升级人类」，交对应小队负责人处理，停止循环。
