# oc-basic

## ⚠️ 执行前必读

1. **首次使用普通 CLI 子命令必须先 `--help`**：当前会话中，每个普通子命令首次业务调用前先运行 `$CLI <command> --help`。
2. **禁止猜测返回结构**：拿到返回值后，先看 JSON 实际层级和字段名，再提取数据。
3. **分页默认只取第一页**：默认只加载第一页（`pageNum=1`）；若结果未完整展示，再询问是否继续。
4. **大输出截断防护**：返回列表数据的命令（如 `file-list`）输出可能因过大被截断，导致 JSON 结构不完整。执行后必须检查 JSON 结构完整性，按以下优先级处理：
   - **正常使用**：JSON 可正确解析且包含文档声明的必要字段 → 正常使用。
   - **保存到文件**：JSON 结构不完整 → 重定向到 `outputs/<随机名>.json` 再读取。
   - **降低分页**：无法写文件 → 减小 `pageSize`（建议从 10 开始）分批获取。
   - **报错**：以上均不可行 → 告知用户输出过大，建议缩小查询范围。

   > 判断依据仅为 JSON 结构完整性，不依赖特定提示文本或项数对比。

生产 Skill 的具体命令、参数和失败处理以对应 `references/` 文档为准；不得调用未在 reference 中定义的入口。下载类命令若返回非 200，必须直接报错并展示响应内容，不要折叠成通用失败。

## 配置（注意系统可能内部注入，不需要提前检查 `.env` 是否存在和正确，详情查看 `.env.example`）

## 命令发现与调用

```bash
$CLI <command> key=value ...
```

`$CLI` = `cli/bin/oc.js`

全局参数：`--help` `--version` `--json` `--verbose`

本技能提供统一 CLI：`cli/bin/oc.js`。普通子命令首次业务调用前使用 `$CLI <command> --help` 获取参数、输入输出和运行时能力，例如 `cli/bin/oc.js file-info fileId=<文件ID> --json`。

## 结果处理

命令返回的结构化结果是权威结果，必须按对应 reference 交给上层渲染；不得伪造卡片、链接、文件 ID 或成功状态。

`file-list` 只输出原始 JSON 结构，不额外构造 `columns` 或 `url`。

## 交互规范

### 多结果确认

当用户意图涉及对特定文件/文件夹的操作，但结果返回多个匹配结果时，必须先列出结果让用户确认目标，不得自动选择。

### 范围推断

用户提到“个人库”时使用 `folderId=2`；提到“企业库”时用 `folderId=1`；未明确时默认企业库并告知用户当前搜索范围。

## 故障排除

### Token 失效（401）

当接口返回 `Status: 401, "No authorization"` 时，检查 API Key 配置和站点地址后重试。不要修改参数格式，也不要调用未在本 Skill 定义的接口。

如果确认 API Key 和站点地址无误仍然失败，应停止并报告认证错误。

## 约束

1. 文件和文件夹 ID 支持数字 ID、GUID 或对应的预览/浏览器地址。
2. `file-list` 默认企业库根目录的 `folderId=1`，个人库根目录使用 `folderId=2`。
3. 上传支持单文件和批量文件；扩展名自动补点，例如 `pdf` 自动转为 `.pdf`。
4. 本 Skill 只提供上述 7 个命令；其它高级文件管理能力不属于本 Skill 范围。
